# Claude Code 인수인계서 — 군인 랜덤 디펜스

작성: 2026-11-19 · 기준 버전: v0.1.0 (첫 시제품)
이 문서는 claude.ai 채팅에서 만들던 작업을 Claude Code가 이어받기 위한 문서다. 이 대화의 내용을 모른다고 가정하고 썼다.

## 1. 한 줄 요약
군별(육군·해군·해병대·특공대·공군·의경)을 고르고, 계급을 올리고 병과를 조합해 100단계를 막는 모바일 랜덤 디펜스 게임. 웹 기술(HTML/JS, 빌드 도구 없음)로 만들고 Capacitor로 Android 앱으로 감싼다. **1차 목표는 Google Play 출시**, 그다음 Steam.

## 2. 가장 먼저 할 일 (중요)
**코드가 아직 GitHub에 올라가 있지 않다.** 저장소 `h0623-dev/soldier-random-defense`(비공개)는 사용자가 만들어 둔 빈 저장소이고, 이전 작업 환경에서는 Claude GitHub 앱 권한이 없어 push가 403으로 거부됐다.

1. 사용자에게 받은 `soldier-random-defense-v0.1.0.zip`을 푼다 (`.git`은 들어 있지 않다).
2. 원격 저장소가 정말 비어 있는지 먼저 확인한다: `git ls-remote https://github.com/h0623-dev/soldier-random-defense`
   - 비어 있으면: `git init -b main && git add -A && git commit` 후 `git remote add origin … && git push -u origin main`
   - 이미 커밋이 있으면: 덮어쓰지 말고 clone해서 내용을 비교한 뒤 사용자에게 확인한다.
3. `npm ci && npm test`가 통과하는지 확인한다.
4. push 후 GitHub Actions "Android 시험 빌드"가 성공하는지 확인한다. **이 빌드는 한 번도 돌려본 적이 없다** — 실패하면 그것부터 고친다.

## 3. 사용자가 정한 규칙
- 게임 데이터·코드는 GitHub(`soldier-random-defense`)에 저장한다.
- 작업할 때마다 인수인계·개발사항을 Notion에 기록한다. 페이지: "군인 랜덤 디펜스 · 개발 기록·인수인계" (기획서 페이지 "군인 랜덤 디펜스"의 하위 페이지). 맨 위 "현재 상태"를 고치고 "작업 기록"에 날짜별 항목을 추가한다. Notion에 접근할 수 없으면 `docs/HANDOFF.md`만 갱신하고 그 사실을 보고한다.
- **다른 게임 저장소(천수 `cheonsu`·`cheonsu-source`, 로드헤이븐, House 등)는 절대 건드리지 않는다.**
- 보고는 한국어. 직접 한 작업 / 검사 / 배포 / 남은 한계를 구분하고, "기능 검사 통과"와 "보기 좋게 완성됨"을 같은 것으로 말하지 않는다.
- 앱 ID, 서명 키, 스토어 등록, 광고·결제 연동은 사용자 확인 없이 정하거나 바꾸지 않는다. 키·토큰을 채팅으로 요청하지 않는다.
- 사용자는 여러 컴퓨터를 오가며 개발한다. 특정 기기에만 있는 설정에 의존하지 말고, 필요한 것은 저장소에 둔다.

   - 8.2 같은 병과끼리 조합하면 상위 같은 병과, 다른 병과끼리 조합하면 두 병과가 연관된 상위 유닛
   - 8.3 보병+보병, 보병+포병, 보병+의료병, 보병+무전병, 포병+의료병 … 처럼 다양한 조합이 가능해야 하고, LV2(일병) 이후에도 조합이 여러 갈래로 이어져야 함

## 6. 게임이 지금 어떻게 동작하는가
- **전장**: 적이 사각 이동로를 계속 돈다. 안쪽 5×5 칸(25칸)에 유닛을 둔다. 전장의 적이 50명을 넘으면 패배. 10단계마다 보스가 나오고 55초 안에 못 잡으면 패배. 100단계 보스까지 잡으면 승리.
- **웨이브**: 24초 간격. 3의 배수는 드론(빠름), 5의 배수는 장갑차(단단함), 10의 배수는 보스.
- **유닛 = 계급 × 병과**. 계급 인덱스가 레벨(이등병 = Lv1).
  - 기본 병과 4종: `inf` 보(단일 속사) / `art` 포(광역) / `med` 의(주변 150px 아군 공속 증가) / `sig` 통(둔화·받는 피해 증가)
  - 유닛의 병과는 기본 병과 2칸 `[a, b]`. 순수 4종 + 혼성 6종 = 10종. 군별로 이름·병기가 다르다 (예: 육군 `inf+art` = 박격포병).
- **조합** (`mergePreview`/`merge`): 같은 등급 두 유닛 → 한 등급 위 유닛 하나. **같은 병과끼리는 그 병과 유지, 다른 병과끼리는 10개 병과 가운데 무작위**(2026-11-20 변경. 이전의 '병과 4칸 세기' 규칙은 없앴다). 최신 규칙은 `docs/DESIGN.md` 뒤쪽 항목을 본다.
- **기획안 1단계 기능**(2026-11-20, `docs/DESIGN.md` 맨 아래 "기획안 1단계"): 병과 교체 · 특수 발판 3칸 · 히든 임무 6개 · 보급 기지(보급병) · 전설의 용사 6종(유니크 기본 병과 둘 → 용사, 전설 유닛과 조합하면 각성) · 특수 병과 고유 기술 6종. 적 체력 증가율은 이때 6.4%로 올렸다.
- **기획안 2단계 기능**(2026-11-20, `docs/DESIGN.md` 맨 아래 "기획안 2단계"): 병과 숙련도 · 부대 표창 18종 · 무한 작전과 보스 러시 · 작전 본부(출석, 일일 임무) · 보급 뽑기판.
- **기획안 3단계 기능**(2026-11-20, `docs/DESIGN.md` 맨 아래 "기획안 3단계"): 행동력 · 보상형 광고 · 보석/고급 보급 상자/스킨 · 랭킹 · 2인 협동. 서버 배포, 광고 ID, 결제 등록은 사용자 몫으로 남아 있다.
- **조작**: 유닛 탭 → 같은 계급 유닛 탭 → 결과 미리보기 → [조합]. 빈 칸 탭은 이동. 선택 상태에서 [전역(판매)].
- **경제**: 신병 소집은 무작위 순수 병과(72% 기본 계급, 22% +1, 6% +2). 훈련소 강화는 소집 기본 계급 +1 (최대 = 계급 수 − 5). 판매는 유닛 가치의 40%.
- **영구 강화**: 훈장(5단계마다 1개, 완주 +20)으로 공격력 +3%/초기 자금 +40/처치 보상 +3%. 기기에만 저장.
- **계급 수 정규화**: 군 5종은 18계급, 의경은 15계급. `expo()`가 레벨을 0~17로 환산해 최종 계급 전투력이 같아진다. 의경은 조합 한 번의 효율이 높아 공격력 −52%로 보정했다 (봇 기준으로 맞춘 값, 거친 보정이다).
- **군별 특성**: 육군 포병 계열 공격력 +15% / 해군 사거리 +10% / 해병대 보병 계열 공속 +15% / 특공대 치명타 15%(2.5배) / 공군 광역 범위 +30%·광역 피해 +10% / 의경 둔화 +30%·보상 +10%·공격력 −52%.

## 7. 검사된 것과 안 된 것
**검사됨**
- `npm test`: 조합 규칙 7개 사례, 군별 10종 병과·병기 3단계 존재, 최종 계급 전투력 동일, 봇 플레이.
- 봇 결과(시드 1·2·3): 대체로 90~100단계에서 패배하거나 간신히 승리. 훈련소를 안 올리는 봇은 60~80단계에서 패배.
- 390×844 휴대폰 크기 브라우저(Chrome)에서 출격 → 소집 → 조합 미리보기 → 조합 → 웨이브 진행 → 도감 화면 동작. 콘솔 오류는 favicon 404 하나뿐.

**검사 안 됨**
- Android APK 빌드와 실제 기기 실행 (한 번도 안 해봄).
- 사람이 100단계까지 직접 플레이한 난이도. 봇은 0.5초마다 최대 40번 조작하고 배치·병과 선택을 하지 않는다. 사람의 체감 난이도는 다를 가능성이 높다.
- 영구 강화가 들어간 상태의 균형, 장시간 플레이 성능, 저사양 기기.

## 8. 알려진 한계
- 그림은 전부 임시 도형(원 + 글자). 캐릭터·병기 그림, 효과음, 배경음이 없다.
- 광고·인앱결제 미연동. 상점은 "준비 중" 버튼만 있다.
- 진행 중 저장/이어하기 없음. 앱이 꺼지면 그 판은 사라진다 (화면이 가려지면 일시정지만 한다).
- 정보창 아래에 빈 공간이 크다. 세로 레이아웃 다듬기 필요.
- 병기 이름은 1차 초안. 계급은 검색으로 확인했지만 병기는 대부분 일반 지식으로 채웠고, 일부 조합(예: 해군 `art+med` 기뢰병, 공군 `art+med` 항공무장정비)은 병과 성격과 억지로 맞춘 것이다. 검수 필요.
- Steam용 PC(가로) 레이아웃 없음.

## 11. 수치를 만질 때 참고
- 모든 균형 수치는 `core.js`의 `CFG`와 `unitStats()`, `waveInfo()`에 모여 있다.
- 핵심 관계: 계급 1단계당 전투력 ×1.9(`growth`), 적 체력 웨이브당 ×1.124(`hpGrowth`), 보상 ×1.098(`bountyGrowth`). `hpGrowth`를 0.004만 바꿔도 봇 결과가 10단계씩 움직인다.
- `window.__srd.game`으로 브라우저 콘솔에서 게임 상태를 볼 수 있다 (자동 검사용 훅).
