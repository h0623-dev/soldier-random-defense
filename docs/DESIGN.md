# 설계 (v0.1.0)

## 기획서 요약
군인 계급·병기 기반 랜덤 디펜스 / 레퍼런스: 워크래프트3 원피스 랜덤 디펜스 / 100단계 / Play 스토어·스팀 / 광고·재화 충전 수익 / 시작 시 군별 6종 선택.

## 전장
- 적은 사각 이동로를 계속 돈다. 전장의 적이 50명을 넘으면 패배. 10단계마다 보스(55초 제한).
- 안쪽 5×5 칸에 유닛 배치. 사거리가 짧은 유닛은 바깥, 포병·의무는 안쪽이 유리.
- 웨이브는 24초 간격. 3의 배수: 드론(빠름), 5의 배수: 장갑차(단단함), 10의 배수: 보스.

## 유닛 = 계급 × 병과
- 계급: 군 5종은 기획서의 18계급(이등병~원수), 의경은 의경 4계급 + 경찰 11계급 = 15계급(이경~치안총감).
  계급 수가 달라도 최종 계급의 전투력은 같도록 정규화했다.
- 기본 병과 4종: 보(단일 속사) · 포(광역) · 의(주변 아군 공속 증가) · 통(둔화·취약).
- 유닛의 병과는 기본 병과 2칸. 순수 4종 + 혼성 6종 = 군별 10종, 군별로 이름과 병기가 다르다.
- 병기 이름은 계급대(병·부사관 / 장교 / 장성)에 따라 3단계로 바뀐다.

## 조합 규칙
같은 계급 두 유닛 → 한 계급 위 유닛 하나. 재료 병과 4칸을 세어
1. 한 병과가 3칸 이상이면 그 병과의 순수 유닛
2. 아니면 가장 많은 두 병과의 혼성 (동률이면 먼저 고른 유닛 우선)
3. 4칸이 모두 다르면 두 유닛의 주병과끼리 혼성

예) 보병+보병=보병, 보병+포병=박격포병, 박격포병+박격포병=박격포병, 박격포병+보병=보병.

## 히든 계급 (국군 5종: 원사·준위)
정규 계급표(18계급) 밖의 특수 계급. 데이터는 `data.js`의 `MIL_HIDDEN`, 규칙은 `core.js`의 `hiddenRecipe()`·`summon()`.
- **원사** — 히든 조합: 상사 + 상사이고 두 유닛의 병과 4칸이 모두 다를 때(보·포·의·통) 소위 대신 원사가 된다. 주변 150px 아군 공격력 +20%.
- **준위** — 뽑기: 훈련소 기본 계급이 하사~상사일 때 신병 소집 1회당 3%. 주변 150px 아군 사거리 +15%.
- 둘 다 전투력·조합 취급은 소위급(Lv8). 조합 재료로 쓰면 일반 계급(중위)으로 진급하고 능력은 사라진다 → 남겨 둘지 합칠지가 선택.
- 같은 종류의 효과는 겹치지 않고 가장 큰 값만 적용. 자기 자신에게는 적용되지 않는다.
- 도감에는 발견 전까지 "???"로 표시되고, 발견하면 기기에 저장(`meta.found`)된다.
- 의경에는 히든 계급이 아직 없다(`hidden: []`).

## 경제
- 신병 소집: 무작위 순수 병과. 72% 기본 계급, 22% +1계급, 6% +2계급.
- 훈련소 강화: 소집 기본 계급 +1 (최종 계급 4단계 아래까지).
- 전역(판매): 유닛 가치의 40% 환급.
- 영구 강화: 훈장(5단계마다 1개, 완주 +20)으로 공격력·초기 자금·처치 보상 강화. 기기에 저장.

## 군별 특성
육군 포병 계열 공격력 +15% / 해군 사거리 +10% / 해병대 보병 계열 공속 +15% / 특공대 치명타 15% / 공군 광역 범위 +30%·광역 피해 +10% / 의경 둔화 +30%·보상 +10%·공격력 -52%(15계급이라 조합 효율이 높아 보정).

## 구조
`www/js/data.js` 데이터 · `core.js` 규칙(순수 로직) · `render.js` 캔버스 · `main.js` 화면/입력/저장 · `monetize.js` 광고·결제 연결 지점(미연동).
Android는 Capacitor로 `www/`를 감싼다. Steam은 같은 `www/`를 Electron 등으로 감싸는 방식을 예정.

## 화면 자동 맞춤 (`www/js/layout.js`)
앱 실행 시와 화면이 바뀔 때(회전, 폴더블 접기/펴기, 창 크기 변경) 화면 크기를 읽어 다음을 정한다.
- **배율**: CSS 크기는 모두 rem(1rem = 10px × 배율). 세로 배치는 `min(폭/390, 높이/640)`을 0.88~1.6으로, 가로 배치는 `min(높이/520, 폭/800)`을 0.85~1.8로 제한. 하한은 글자가 너무 작아지지 않게, 상한은 태블릿에서 버튼 대신 전장이 커지게 하려는 것.
- **배치**: 폭 > 높이×1.15이면 가로 배치(왼쪽 전장, 오른쪽에 상단바·정보창·버튼), 아니면 세로 배치.
- **전장 크기**: 세로는 `min(폭, 남는 높이)`, 가로는 `min(높이, 폭 − 오른쪽 패널 최소 폭)`. 전장 비율(720:700)은 고정.
- **세로로 긴 화면**: 남는 높이 일부를 버튼·상단바 높이로 돌린다(`--vy`).
- **캔버스 해상도**: 표시 크기 × 기기 픽셀 비율(품질 단계별 상한 2.5 / 1.5 / 1). 프레임 시간이 2.5초 이상 계속 28ms를 넘으면 품질을 한 단계 내린다(느린 기기 자동 조정). 한 번 내린 품질은 그 실행 동안 다시 올리지 않는다.
- 검사: `npm run serve` 후 `node tests/screens.cjs <폴더>` — 23개 화면 크기에서 화면 밖 요소, 가로 스크롤, 정보창 넘침, 칸·버튼·글자 크기를 확인하고 스크린샷을 남긴다.

## 캐릭터 그림 (`www/js/sprites.js`)
그림 파일 없이 코드로 그리는 2등신 캐릭터. 조합 수가 많아(6군별 × 10병과 × 계급) 부품을 조합하는 방식으로 했다.
- 군별 → 군복 색·모자: 육군·해병대 철모, 해군 수병모, 특공대 베레모, 공군 약모, 의경 경찰모.
- 병과 → 장비: 보 소총 / 포 포신 / 의 구급낭 / 통 무전기·안테나. 혼성 병과는 양쪽에 하나씩 든다.
- 계급대(병기 3단계와 같은 구간) → 병·부사관: 기본 모자 / 장교: 정모 / 장성: 금테 정모·견장·카드 오른쪽 위 별.
- 유닛 카드: 병과 색 발판, 왼쪽 위 병과 글자, 아래 계급 이름표(장교 은색·장성 금색 테두리), 히든 계급은 금색 점선.
- 적: 보병, 드론, 장갑차, 지휘 전차(보스). 둔화는 파란 원, 취약은 노란 테.
- 같은 그림은 `sprite()` 캐시에 한 번만 그려 두고 복사한다(화면 배율이 바뀌면 다시 그림).
- 정식 화풍이 정해지면 `drawSoldier()`·`ENEMY_DRAW`만 바꾸거나 이미지 파일로 교체하면 된다.

### 그림 파일 (만화풍, 2026-11-19 적용)
`www/img/manifest.json`에 등록된 그림이 있으면 코드 그림 대신 그림 파일을 쓴다(군별 10병과가 모두 있을 때만). 유닛은 `www/img/units/<군별>_<병과>.webp`, 적은 `www/img/enemy_<종류>.webp`. 원본·지시문은 `art/raw_figma/`, `art/jobs_figma.json`. 다시 만들 때: 원본 교체 → `python3 -I tools/cutout.py <원본 폴더> <출력 폴더>` → 파일을 위 위치로 옮김.

### 유닛 카드 구성 (2026-11-19 보완)
- 세 겹: 카드 뒤(병과 색 발판, 히든 테두리) → 캐릭터(숨쉬기·사격 반동) → 카드 앞(계급장, 이름표).
- 계급장(오른쪽 위): 계급마다 [모양, 개수]. 병 막대 / 부사관 갈매기 / 위관 다이아 / 영관 꽃 / 장성 별. 데이터는 `data.js`의 `MIL_INSIG`, `POLICE_INSIG`, 히든 계급의 `insig`.
- 이름표(아래): 병과 글자(보·포·의·통) + 계급 이름. 테두리 색은 계급대(기본/은/금), 히든은 금색.

## 효과음 (`www/js/sound.js`)
소리 파일 없이 Web Audio로 합성. `core.js`는 사격 때 `g.sfx`에 병과를, 보스 격파 때 `bossdie`를 넣고, `main.js`가 매 프레임 꺼내 재생한다(같은 소리는 최소 간격을 둬 겹치지 않게). 웨이브 시작·보스 등장은 `g.log`를 보고 낸다. 설정은 `meta.mute`.

## 자동 업데이트 (`www/js/update.js`, `www/sw.js`, `tools/make-update.mjs`)
APK를 다시 설치하지 않아도 게임 내용(화면·규칙·그림·소리 = `www/` 전체)을 앱 실행 시 내려받아 바꾼다.
- **흐름**: 앱 실행 → `update-config.json`의 `url`에서 `version.json`을 읽음 → 빌드 번호가 지금 것(앱에 든 것, 이미 받아 둔 것)보다 크면 목록의 파일을 모두 받아 캐시 `srd-live-<빌드>`에 저장 → 아직 게임을 시작하지 않았으면 바로 다시 열고, 게임 중이면 다음 실행부터 적용. `sw.js`(서비스 워커)가 받아 둔 파일을 앱에 든 파일 대신 내준다.
- **인터넷이 없을 때**: 가지고 있는 버전(받아 둔 것 또는 앱에 든 것)으로 그대로 실행.
- **새 APK 설치**: 앱에 든 빌드가 받아 둔 것 이상이면 받아 둔 것을 버린다.
- **고장 난 업데이트**: 받은 버전이 5초 안에 못 뜨거나 지난 실행에서 못 떴으면 버리고 앱에 든 버전으로 복구, 그 빌드는 다시 받지 않는다(`index.html`의 시작 점검, `srd_live_bad`).
- **빌드 번호**: 마지막 커밋 시각(초). `npm run bundle`이 `www/version.json`(앱용, git에는 올리지 않음)과 `dist/update/`(호스팅에 올릴 폴더)를 만든다. APK를 직접 빌드할 때도 `npx cap sync` 전에 `npm run bundle`을 먼저 실행한다.
- **배포**: `.github/workflows/android.yml`이 main push 때 `dist/update`를 Cloudflare Pages에 올린다. 저장소 Secrets `CLOUDFLARE_API_TOKEN`·`CLOUDFLARE_ACCOUNT_ID`, Variables `CF_PAGES_PROJECT`가 있을 때만 동작. 다른 호스팅을 쓰려면 이 단계만 바꾸면 된다(필요 조건: `dist/update` 폴더를 그대로 올리고, 모든 출처에서 받을 수 있게 CORS 허용).
- **자동 업데이트가 안 되는 것**: 앱 껍데기(Android 쪽) 변경 — 앱 ID, 아이콘, 권한, 광고·결제 같은 기기 기능 추가, `sw.js` 자체. 이런 변경은 새 APK(또는 스토어 업데이트)가 필요하다.
- 켜는 법: `www/update-config.json`의 `url`에 호스팅 주소를 넣는다. 비어 있으면 꺼져 있다.

## 전장 모양과 입체 표현 (2026-11-19 변경)
- **전장**: 720×880의 세로로 긴 형태. 이동로는 모서리가 둥근 긴 사각 순환로(60,70)~(660,820), 안쪽에 발판 5×5(가로 간격 100, 세로 간격 124). 지원 범위(`auraRadius`)는 대각선 이웃까지 닿도록 165.
- **입체 표현**(`render.js`): 위에서 비스듬히 내려다본 느낌. 바닥은 두께(옆면)가 있는 진지 바닥판과 발판, 길은 살짝 파인 흙길. 캐릭터는 네모 카드 없이 발판 위에 서 있고(발판보다 크게, 위로 겹침), 아래쪽 줄이 위쪽 줄을 가린다. 발밑에 그림자와 병과 색 띠, 히든 계급은 금빛 원.
- **표시**(`sprites.js`의 `drawTag`): 발 아래 이름표(병과 글자 + 계급), 머리 오른쪽 위 계급장.
- 움직이지 않는 배경은 한 번만 그려 두고 복사한다(`background()`).

공격할 때 병과 조합마다 다른 것이 날아가 맞는다(`render.js`의 `shot()`, 0.36초). 피해는 전처럼 발사 순간에 들어가고, 이펙트는 보여 주기만 한다.

## 난이도 · 이어하기 · 피해 기록 (2026-11-20)
- **난이도**(`core.js`의 `DIFFS`): 보통 / 어려움(적 체력 1.8배, 훈장 1.6배) / 지옥(3배, 2.5배). 바로 아래 난이도에서 50단계까지 가면 열린다. 최고 기록은 난이도별로 따로 둔다(보통 `meta.best`, 그 위 `meta.bestD[난이도]`). 군별 선택 화면에서 고른다.

- **메뉴**: "저장하고 나가기"와 "포기하고 결과 보기"(지금까지의 기록으로 훈장을 받는다)로 나눴다.
- **누적 피해**: 유닛마다 실제로 깎은 체력을 더한다(`u.dealt`, 조합하면 두 유닛 것을 이어받음). 유닛 카드에 표시하고, 결과 화면에 최우수 유닛과 병과별 피해 비율을 보여 준다.

## 계급 7단계 (2026-11-20, 사용자 결정) — 앞의 18계급 설명을 대체한다
"계급이 너무 많아 끝까지 조합하기가 빡세다, 다른 게임처럼 일반~초월 정도로" → 18계급(의경 15)을 **7계급**으로 줄였다. 화면에서는 등급 이름 없이 **색으로만** 구분하고 등급 이름은 도감에만 적는다.

| 등급(도감) | 색 | 국군 | 의경 | 계급장 | 그림(계급대) |
|---|---|---|---|---|---|
| 일반 | 회색 | 이등병 | 이경 | 막대 1 | 기본 |
| 고급 | 초록 | 병장 | 수경 | 막대 4 | 기본 |
| 희귀 | 파랑 | 상사 | 경사 | 갈매기 | 부사관(t1) |
| 영웅 | 보라 | 대위 | 경감 | 다이아 | 위관(t2) |
| 유니크 | 주황 | 대령 | 총경 | 꽃 | 영관(t3) |
| 전설 | 금색 | 대장 | 치안정감 | 별 | 장성(t4) |
| 초월 | 빨강 | 원수 | 치안총감 | 별 | 장성(t4) |

- **데이터**(`data.js`): `MIL_RANKS`, `POLICE_RANKS`, `GRADES`(이름·색), 계급장, 병기 단계 `[3, 5]`(대위부터 2단계, 대장부터 3단계). 히든 계급은 그대로 — 원사 = 상사 + 상사(병과 4칸이 모두 다를 때), 준위 = 훈련소 기본 계급이 상사~대위일 때 소집 3%. 둘 다 대위급으로 취급.
- **색 표시**: 유닛 받침대(병장부터 등급 색 원판), 이름표 테두리, 유닛 카드·조합 미리보기의 이름 앞 색 점, 도감의 계급표. 크기는 계급 순으로 조금씩 커진다.
- **경제를 통째로 다시 잡았다**(`core.js`의 `CFG`). 계급 수만 줄이면 조합 한 번에 전투력이 6배씩 뛰어, 조합이 압도적으로 이득이 되고 10단계쯤에 원수가 나온다. 그래서:
  - 한 계급 = 전투력 1.9배 = 아래 계급 2명(조합은 전처럼 "자리 아끼기"이지 전력 이득이 아니다). 원수 = 이등병 64명분.
  - 군자금 수입을 낮추고 완만하게: 처치 보상 `bountyBase` 0.3 × 1.055^단계, 단계 보너스 고정 15(`waveBonus`).
  - 적 체력 `hpGrowth` 1.059(전 1.129). 훈련소는 4단계(최고 = 대위 소집), 올릴 때마다 같은 전력이 20% 싸진다(`summonGrowth` 1.6). 병과 강화는 50 × 1.35^단계.
  - 소집 행운: 한 계급 위 15%, 두 계급 위 3%. 진급 심사 성공률은 계급별 55 · 45 · 35 · 22 · 12%이고 **대장부터는 받을 수 없다**(원수는 조합으로만).
  - 보스마다 체력 배수(`boss.hpMul`)를 따로 둔다. 봇으로 재 보니 보스 능력·맵 때문에 잡는 시간이 17~102초로 들쭉날쭉해서(40·90·100단계가 유난히 김) 단계 순으로 고르게 어려워지게 맞췄다.
  - 난이도 배수: 어려움 1.3배, 지옥 1.7배(전 1.8배·3배). 화력과 적 체력이 나란히 자라서 배수가 조금만 커도 훨씬 일찍 막힌다.
- **봇 기준 진행 속도**(보통 난이도): 대위 5단계쯤, 대령 10~20단계, 대장 50~70단계, 원수 80단계쯤 첫 등장, 100단계에서 원수 21명 안팎. 봇 승률은 군별 합쳐 절반쯤(특공대 강함, 해병대·의경 약함).
- **그림**: 의경에도 위관급(t2, 경감) 그림이 필요해져 지시문 5장을 추가했다(`art/jobs_soft.json` 148~152번).
- 저장 형식을 올렸다(`SAVE_V` 2). 이전에 저장한 진행 중 게임은 이어할 수 없다(최고 기록·훈장은 그대로).

## 등급 이름 · 등급 안의 계급 이름 · 계급장 모양 (2026-11-20, 사용자 지정) — 바로 위 "계급 7단계"의 표를 대체한다
사용자: "병장·상사·대위만 있으니 계급이 너무 없어 보인다. 같은 등급에서 병과에 맞춰 계급 표시만 다르게, 등급 이름은 노말·매직…으로, 군별에 맞는 계급 이름으로, 하사·중사·상사 계급장은 진짜 모양으로."

| 등급(색) | 국군 | 의경 |
|---|---|---|
| 노말(회색) | 훈련병 (해병대는 훈병) | 교육생 |
| 매직(초록) | 이등병 · 일병 · 상병 · 병장 | 이경 · 일경 · 상경 · 수경 |
| 레어(파랑) | 하사 · 중사 · 상사 | 순경 · 경장 · 경사 |
| 영웅(보라) | 소위 · 중위 · 대위 | 경위 · 경감 · 경정 |
| 유니크(주황) | 소령 · 중령 · 대령 | 총경 · 경무관 |
| 전설(금색) | 준장 · 소장 · 중장 · 대장 | 치안감 · 치안정감 |
| 초월(빨강) | 원수 | 치안총감 |

- **조합·전투력은 등급으로만 정해진다.** 한 등급 안의 계급 이름은 표시일 뿐이다(`data.js`의 `rankOf(군별, 등급, 병과)`).
- **어느 이름을 쓰나**: 병과 순서 `의무 · 통신 · 보병 · 포병 · 의+통 · 보+의 · 보+통 · 포+의 · 포+통 · 보+포`에서의 위치를 그 등급의 이름 수로 나눈다. 순수 병과는 아래 계급, 혼성 병과는 위 계급 이름이 된다. 예: 매직 등급 보병 = 이등병, 포병 = 일병, 보+의 = 상병, 보+포 = 병장.
- **군별**: 국군(육·해·공·해병)은 법으로 계급 이름이 같아 표가 같다. 해병대만 훈련병을 '훈병'으로 했다. 의경은 의무경찰 4계급 + 경찰 계급(총경 위가 4계급뿐이라 유니크·전설은 이름이 둘씩). 특공대는 국군 표를 쓴다.
- **계급장 모양**(`sprites.js`의 `drawInsig`): 병 = 가로 막대를 위아래로 1~4개, 부사관 = 아래로 뾰족한 V자를 1~3개 겹침(원사는 V자 3 + 별), 위관 = 다이아몬드 1~3, 영관 = 무궁화 1~3, 장성 = 별 1~4(원수 5), 훈련병 = 없음. 의경은 순경~경사 무궁화 봉오리 2~4, 경위~총경 무궁화 1~4, 경무관 이상 큰 무궁화 1~4.
- **그림 계급대**는 등급으로 정한다(`GROUP_OF_LEVEL` = 기본 · 기본 · 부사관 · 위관 · 영관 · 장성 · 장성). 히든 계급은 따로(`grp`: 원사 = 부사관, 준위 = 위관).
- 화면: 전장은 색(받침대·이름표 테두리)과 계급 이름·계급장, 유닛 카드에는 등급 이름도 표시, 도감에 등급표. 임무·훈련소·소집 버튼의 문구는 등급 이름을 쓴다("영웅 등급 이상 1명 보유", "매직~").

## 조합 규칙 — 같은 병과는 유지, 다른 병과는 무작위 (2026-11-20, 사용자 지정)
앞의 "병과 4칸을 세어 결과를 정하는" 규칙을 없앴다.
1. **같은 병과 + 같은 병과 → 같은 병과**로 한 등급 진급. (보병 + 보병 = 보병, 박격포병 + 박격포병 = 박격포병)
2. **다른 병과끼리 → 한 등급 진급하되 병과는 무작위**. 그 군별의 10개 병과(기본 4 + 특수 6) 가운데 고르게 뽑는다.
- 특수 병과 6종(박격포병·전투의무병 등, 이전의 '혼성 병과')은 이제 다른 병과끼리 조합할 때만 나온다. 능력은 전처럼 두 기본 병과의 절반씩이다.
- 코드: `core.js`의 `TYPE_KEYS`, `sameType`, `mergePreview`(`random: true`면 병과 미정), `merge`(조합하는 순간 난수로 정함).
- 화면: 유닛을 고르면 조합할 수 있는 칸 가운데 **같은 병과는 노란색, 다른 병과는 보라색 점선**으로 표시한다. 미리보기는 같은 병과면 결과와 능력치를, 다른 병과면 물음표와 설명을 보여 준다. 도감의 조합 부분도 새 규칙으로 바꿨다.
- 히든 조합(원사)은 그대로: 레어 등급 둘의 병과 4칸이 모두 다를 때. 이때도 병과는 무작위다.
- 봇 결과는 이전과 비슷하다(24판 중 11승) — 병과가 고르게 섞이는 평균은 같기 때문.

## 인게임 화면 — 주둔지 (2026-11-20, 사용자가 시안 E 선택)
"버튼이 너무 많아 게임 화면이 잘 안 보인다" → 시안 5종(`art/sian/ui_concepts/`) 가운데 E를 골랐다. 버튼 줄을 없애고 **전장 아래 주둔지의 건물**을 누르게 했다.
- **상단바 한 줄**: 단계와 지역 이름 · 다음 웨이브/적 수 막대 두 줄 · 군자금 · 보급품 · 속도 · 메뉴. (전에는 두 줄)
- **주둔지**(`index.html`의 `#actions`): 전장과 같은 땅 색 위에, 전장 발판과 같은 색의 판을 놓고 건물 5채를 세웠다. 건물 아래 팻말에 기능과 값이 적힌다.

| 건물 | 기능 | 팻말 |
|---|---|---|
| 천막 | 훈련소 강화 | 훈련소 Lv · 비용 |
| 병기창 | 병과 강화(창이 뜬다) | 합계 Lv |
| 연병장(가장 큼) | 신병 소집 | 소집 등급 · 비용 |
| 보급창 | 선택 소집(창이 뜬다) | 보급품 개수 |
| 통신탑 | 특수 임무 | 출동 가능 / 진행 / 대기 |

  - 쓸 수 없으면 건물이 회색으로 흐려지고, 특수 임무를 부를 수 있으면 통신탑이 빛난다.
  - 주둔지 위쪽 한 줄: 다음 단계 안내 + 임무 버튼. 세로로 긴 화면(`#app.tall`)에서는 남는 자리에 이 지역 보스 안내(그림·능력)를 보여 준다.
  - 조합 도감은 메뉴(≡) 안으로 옮겼고, 메뉴에 임무도 넣었다.
  - 건물은 지금 SVG로 그린 것이다. 그림 AI로 만든 건물 그림으로 바꿀 수 있다(`index.html`의 `<svg>`를 `<img>`로).
- **유닛을 고르면** 주둔지 위에 유닛·조합 카드가 겹쳐 뜨고 건물은 흐려진다(`#info`와 `#actions`가 같은 자리). 평소에는 카드가 없다.
- **배치 계산**(`layout.js`): 전장은 폭에 맞추고, 상단바와 주둔지 최소 높이(16.5rem, 짧은 화면 13.2rem)를 뺀 높이를 넘지 않게. 주둔지가 남는 높이를 모두 쓴다. 건물 크기는 주둔지의 높이·폭에 맞춰 0.72~1.6배(`--bs`).
- 지역이 바뀌면 주둔지와 전장 바깥의 땅 색, 건물 판 색도 그 지역 색으로 바뀐다(`render.js`의 `areaColors`).
- 화면 크기 검사(23종)에서 전에 걸리던 iPhone SE 1세대도 통과한다(아래 UI가 낮아져 전장이 커짐: 칸 39px → 44px).

## 기획안 1단계 — 협타디 대조에서 나온 6개 항목 (2026-11-20, 사용자 "1단계부터 순서대로 진행")

배경과 조사 내용은 `docs/PLAN_COOPTD_GAP.md`. 구조만 참고하고 이름·수치는 우리 것으로 새로 정했다.

### 병과 교체
- 유닛 카드의 "병과 교체" 버튼. 보급품 `CFG.rerollSupply`(1)개.
- 지금 병과를 뺀 9종 가운데 무작위. 등급·누적 피해·자리는 그대로. 조합 규칙이 "다른 병과끼리는 무작위"가 된 뒤, 원하는 병과를 맞추는 수단이다.

### 특수 발판
| 종류 | 효과 | 색 |
|---|---|---|
| 속사 발판 | 공격 속도 +25% | 하늘색 |
| 고지 발판 | 사거리 +20% | 연두색 |
| 급소 발판 | 치명타 확률 +15% (치명타 = 2.5배) | 주황빛 분홍 |
- 지역에 들어설 때마다(게임 시작, 10단계마다) 발판 25칸 가운데 3칸이 종류마다 하나씩 무작위로 정해진다(`g.tiles = {칸 번호: 종류}`). 저장에 포함.
- 그 칸 위에 선 유닛만 효과를 받는다. 의무병 지원(공속)·히든 계급 지원(사거리)과는 더해진다.
- 봇은 가장 높은 등급의 유닛을 특수 발판에 세운다.

### 히든 임무
| id | 조건 | 보급품 |
|---|---|---|
| h_mono | 같은 병과 유닛 8명을 동시에 보유 | 3 |

- 상단 임무 버튼의 숫자(n/15)는 일반 임무만 센다.

### 보급 기지
- 보급창 건물 → "보급창" 창의 맨 위. 보급병 최대 `depotMax`(10)명, 고용 비용 `depotBase`(20) × `depotGrowth`(1.35)^고용한 수 → 20, 27, 36, 49, 66, 90, 121, 163, 221, 298 (합계 약 1,090).
- 단계가 시작될 때 보급병 한 명당 `depotFlat`(1) + 그 단계 기본 수입(단계 보너스 15 + 적 수 × 처치 보상)의 `depotRate`(3%). 예: 10명이면 1단계 +16, 30단계 +23쯤, 60단계 +57쯤, 100단계 +460쯤.
- 5단계마다 보급병 5명당 보급품 1개.
- 봇 기준 10명을 다 고용하면 한 판에서 번 군자금의 22%쯤이 보급 기지에서 나온다. 일찍 고용하면 초반 전력이 줄어서 승률에는 거의 영향이 없었다(선택의 문제로 남는다).

### 전설의 용사
조합식: **유니크 등급 · 기본 병과 · 서로 다른 병과** 둘 → 전설 등급 용사(병과는 두 재료를 섞은 특수 병과로 고정). 모든 군별 공통.

| 용사 | 재료 | 기술 (전설) | 각성 (초월) |
|---|---|---|---|
| 강철비 | 보병 + 포병 | 6초마다 전장의 모든 적에게 공격력의 100% | 160% |
| 불사조 | 보병 + 의무 | 아군 전체 기절·화염 면역, 공격력 +6% | +10% |
| 매의 눈 | 보병 + 통신 | 사거리 무제한, 체력 가장 많은 적, 치명타 확률 +50% | 치명타 4배 |
| 불바다 | 포병 + 의무 | 맞은 자리에 4초 화염 지대(초당 공격력의 25%) | 40% |
| 동장군 | 포병 + 통신 | 8초마다 사거리 안의 적 1.5초 빙결(보스·정예 절반) | 2.5초 |
| 총사령관 | 의무 + 통신 | 아군 전체 공격 속도 +12% | +20% |

- 용사는 **종류마다 한 명**. 이미 있는 용사의 조합식은 일반 조합(병과 무작위)이 된다. 전체 효과는 같은 종류끼리 겹치지 않는다.
- **각성**: 용사 + 전설 등급 유닛(아무 병과) → 초월 등급 용사. 두 용사를 조합하면 먼저 고른 쪽이 각성하고 다른 쪽은 사라진다.
- 용사는 진급 심사·병과 교체를 받을 수 없다. 전역은 된다.
- 구현: 유닛의 `hidden` 칸에 용사 id를 쓴다(히든 계급과 같은 칸, 정의에 `hero: true`). `hiddenDef`가 둘 다 찾고 `heroOf(u)`가 용사만 돌려준다. 전체 효과는 `g.buff`, 화염 지대는 `g.zones`, 빙결은 적의 `freezeT`.
- 화면: 조합할 수 있는 칸 가운데 용사(또는 히든 조합)가 되는 짝은 붉은 테두리 + 별. 용사는 발밑이 용사 색으로 타오르고 각성하면 금색 점선 고리가 더 붙는다. 이름표에는 용사 이름이 금색으로 나온다.
- **처음 수치는 훨씬 강했다**(강철비 150%, 총사령관 +20% 등, 중복 허용). 봇이 한 판에 용사 10~20명을 만들어 전부 이겼기 때문에 한 명 제한을 두고 지금 수치로 낮췄다.

### 병과 고유 기술 (특수 병과 6종)
| 병과 조합 | 육군 이름 | 기술 | 내용 |
|---|---|---|---|
| 보+포 | 박격포병 | 연속 포격 | 3번째 공격마다 피해 +50% · 광역 범위 2배 |
| 보+의 | 전투의무병 | 응급 처치 | 이웃한 아군의 기절·화염 시간 절반 |
| 보+통 | 수색정찰병 | 조준 사격 | 치명타 확률 +10% |
| 포+의 | 화생방병 | 오염 | 맞은 적에게 3초간 초당 공격력의 12% |
| 포+통 | 포병관측병 | 표적 지정 | 맞은 적이 받는 피해 +30% (4초) |

- 기본 병과 4종은 고유 기술이 없는 대신 같은 병과끼리 조합하면 병과가 유지되고, 용사의 재료가 된다.
- 용사도 병과가 특수 병과이므로 그 병과의 고유 기술을 함께 가진다.

### 난이도 재조정 (같은 날)
- `CFG.hpGrowth` 1.059 → **1.064** (적 체력이 단계당 6.4%씩). 다른 수치는 그대로.

## 기획안 2단계 — 전투 밖 성장과 새 모드 (2026-11-20, 사용자 "2단계도 순서대로 진행")

로직은 `www/js/meta.js`(화면과 분리된 순수 함수, `tests/sim.mjs`에서 검사)와 `core.js`에 있다. 기기에 저장되는 값은 `localStorage`의 `srd_meta_v1` 하나(`M.fillMeta`가 예전 저장에 새 칸을 채워 준다).

### 병과 숙련도
- 칸: 군별 6 × 병과 10 = 60. `meta.xp = { 군별: { 병과 키: 경험치 } }`.
- 한 판의 경험치 = 도달 단계 × 10 × 난이도 훈장 배수(보스 러시는 잡은 보스 × 100). 그 판에서 **준 피해 비율**대로 병과에 나눈다(`g.dmgT`에 병과 키별 피해를 기록).
- 다음 단계까지 필요한 경험치 = 100 + 60 × 지금 단계 → 10단계까지 합계 3,700. 한 단계마다 그 병과 공격력 +2%(최고 +20%). `core.js` `MASTERY`, `masteryInfo`, `unitStats`.
- 뽑기판의 "숙련 교본"은 무작위 군별·병과에 +150.

| 보스 러시 | 30단계 도달 | 보스 10종만 연달아. n번째 보스 = 기본 작전 10n단계 보스. 시작할 때와 보스를 잡을 때마다 군자금(기본 작전에서 그 앞 아홉 단계 동안 버는 돈 × 1.3)과 보급품 3개를 받고 다음 지역으로 옮긴다. 다음 보스는 15초 뒤(첫 보스는 20초 뒤), 보스가 살아 있는 동안에는 시간이 가지 않는다 | `bestR`(잡은 보스 수) | 보스 하나에 2 + 승리 10 |
- 난이도(보통·어려움·지옥)는 세 모드 모두에 적용된다. 무한 작전·보스 러시의 기록은 난이도를 구분하지 않는다.
- 보스 러시에서는 특수 임무를 쓸 수 없고, 달성할 수 없는 임무(처치 300·1000, 30·60단계, 특수 임무, 위기 탈출)는 목록에서 뺀다. 보급병 수입은 판마다 받는 군자금을 기준으로 계산한다.
- 봇: 보스 러시 보통 36/48승(군자금 배수 1.0에서는 절반 이상이 3·5번째 보스에서 져서 1.3으로 올림). 무한 작전은 112단계쯤.
- 구현: `g.mode`, `maxWaveOf(g)`, `waveOf(g, wave)`, `areaOf(g, wave)`, `rushStipend(n)`, `enterArea`, `reached(g)`. 저장(`saveGame`)에 모드가 들어간다.

## 2인 협동 — 한 전장 나눠 쓰기 (2026-11-20, 사용자 "협타디처럼 한 맵을 나눠 쓰는 방식으로")

### 규칙
| 함께 쓰는 것 | 플레이어마다 따로 |
|---|---|
| 전장(맵·길), 적, 단계, 보스 제한 시간, 특수 발판, 임무, 특수 임무 대기 시간, 용사(종류마다 한 명) | 군별, 군자금, 보급품, 훈련소, 병과 강화, 보급병, 유닛, 영구 강화·표창·숙련도 |
- **구역**: 발판 25칸 가운데 위쪽 `duoSplit`(13)칸이 방장, 아래 12칸이 손님. 자기 구역에만 소집되고, 자기 유닛을 자기 구역 안에서만 옮긴다. 조합·전역·진급 심사·병과 교체도 자기 유닛만.

- **함께 쓰는 표창**: 특수 발판 수(공병)와 보스 제한 시간(방어 유공)은 둘 중 높은 쪽.
- **적 체력**: 혼자 할 때의 `duoHp`(1.1)배. 두 사람이 저마다 수입을 받지만 훈련소·병과 강화도 저마다 올려야 하고 용사도 전장에 종류마다 한 명이라 화력이 2배가 되지 않는다(봇 기준 1.0배 69%, 1.15배 50% 승리).

- 한쪽이 나가면 남은 사람이 **전장 전체를 맡는다**(동료 유닛도 다룰 수 있다. 동료의 군자금은 쓰지 못한다).

### 구현
- `core.js`: `createDuo({ players, seed, me })`. 플레이어별 값은 `g.duo.ps[i]`에 있고, `g.gold`·`g.branch`·`g.up` 같은 이름은 **지금 다루는 플레이어(`g.duo.cur`)**의 값을 가리키는 접근자다(`bindDuo`). 그래서 혼자 하는 판의 규칙 코드와 화면 코드를 그대로 쓴다. 평소 `cur`는 이 기기의 플레이어이고, 명령은 `act(g, i, f)`로, 모두에게 주는 것은 `each(g, f)`로 잠깐 바꾼다.
- **`step()` 안에서는 `cur`에 기대면 안 된다**(기기마다 다르다). 플레이어별 값은 `each()`나 유닛의 주인(`u.o`)으로만 읽는다. 이것이 깨지면 두 기기의 계산이 어긋난다.
- 조작은 모두 `exec(g, i, [이름, 값…])` — `summon` `pick` `camp` `up` `merge` `move` `sell` `gamble` `reroll` `elite` `hire` `ad` `gift`.
- **동기화**(`main.js`): 방장이 0.05초 걸음을 세며 `tk`(지금 걸음)와 `cmd`(이 걸음에 이 명령)를 보낸다. 손님은 방장이 알려 준 걸음까지만 나아가며 같은 걸음에 같은 명령을 실행한다. 손님의 조작은 `req`로 방장에게 보내고 `cmd`로 돌아온 것을 실행한다. 40걸음마다 `sum`(`duoHash`)을 견주고, 다르면 `need` → `snap`으로 방장의 상태를 통째로 받는다.
- 서버는 글을 넘기기만 한다(`server/`). 글 크기 제한은 20만 자(상태 통째가 수만 자).

## 대기실(작전 본부) 화면 (2026-11-20, 사용자 제보로 다시 짬)
- **한 화면에 다 들어와야 한다.** 스크롤이 생기면 안 된다(가장 짧은 360×560, 이어하기 버튼이 있을 때도).
- 짜임새: 위 = 프로필·재화 / 양옆 = 그림 버튼(왼쪽은 매일 하는 것, 오른쪽은 성장) / 가운데 = 일러스트와 제목 / 아래 = 큰 출격 버튼과 2인 협동.
- 새 기능을 넣을 때는 양옆 열에 그림 버튼으로 더한다(한 열 4개까지). 받을 것이 있으면 빨간 점.
- 출석·일일 임무처럼 줄이 여러 개인 것은 대기실에 펼치지 않고 따로 화면을 둔다(`ACT.daily`).
