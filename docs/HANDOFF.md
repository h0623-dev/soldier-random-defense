## 2026-11-21 — 전장 이름표를 캐릭터 이름으로 · 배속 기준을 2배로
**경위**: 사용자(실제 기기 화면 첨부) — "계급 말고 캐릭터 이름으로 나오게 해 줘. 지금 1배속이 기본인데 2배속을 기본으로 하고 그 속도를 1배율로 보이게, 그때부터 배속 버튼을 누르면 빨라지게".
**직접 한 작업**
- **전장 이름표**: `군별 + 계급` → `군별 + 캐릭터 이름`(예: 육군 바둑이, 의경 부리부리). 계급은 머리 위 계급장과 발밑 원판 색, 유닛 카드에서 본다. (`sprites.js` `drawTag`의 `o.nick`, `render.js` `unitTags`)
- **배속**(`main.js` `SPEEDS = [2, 4, 6]`): 예전 2배속이 기본이고 화면에는 ×1로 보인다. 버튼을 누르면 ×1 → ×2 → ×3(실제 2 · 4 · 6배). 협동도 같은 값(방장이 정함, 모르는 값은 기본으로).
**검사**: 표시 ×1 · ×2 · ×3에서 게임 시간이 실제의 2.0 · 4.0 · 6.0배로 흐르는 것을 재서 확인. 이름표는 여섯 군별 × 여러 병종으로 채워 눈으로 확인(가장 긴 `의경 부리부리`도 칸 안). `npm test` 통과, 화면 검사 문제 기기 0.
**남은 한계**: 실제 기기 미확인 — 특히 ×3(실제 6배)이 느린 기기에서 버벅이지 않는지. 전장에서 계급 이름은 이제 보이지 않는다(히든 계급 원사·준위도 이름표에서는 캐릭터 이름). 사용자가 보낸 화면에 하단 내비게이션 바가 보인다 — 시험판-3 APK를 깔았는지 확인 필요.

## 2026-11-21 — 병과 글자(보·포·의·통) 표시를 없애고 군별 이름으로, 유닛 카드는 "군별 · 병기 · 계급 / 이름"

**검사**: 여섯 군별 × 등급 섞은 전장과 유닛 카드를 두 화면 크기에서 눈으로 확인(가장 긴 `해병대 이등병`, `의경 치안총감`도 칸 안에 들어간다). `npm test` 통과, 화면 검사 문제 기기 0, 콘솔 오류 0.

## 2026-11-21 — 빈 칸을 눌러 소집 · 발밑 등급 원판 · 유닛 카드의 바로 조합 버튼
**경위**: 사용자(레퍼런스 전투 화면 2장 첨부) — "신병 소집을 눌러 랜덤 뽑기가 아니고 내가 원하는 지형을 눌렀을 때 소집되게. 등급 구분이 어려우니 협타디처럼 밑에 원판으로 등급이 명확하게 보이게. 유닛을 눌렀을 때 조합(합성) 버튼이 떠서 누르면 바로 조합되게 — 동일 병과 조합, 랜덤 조합 두 개. 조합이 가능할 때만 켜지고 안 되면 회색으로 눌리지 않게".
**직접 한 작업**
- **빈 칸을 누르면 그 자리에 소집**: `core.js` `summon(g, 칸)`(칸을 주지 않으면 예전처럼 무작위 — 봇·검사용), 명령 `['summon', 칸]`(협동에서도 그대로 전해진다, 동료 칸에는 안 됨). 아래 "신병 소집" 건물은 값 표시로 남기고, 누르면 소집하지 않고 빈 칸을 잠깐 빛내며 "소집할 빈 칸을 누르세요"라고 알린다.
- **발밑 등급 원판**(`render.js`): 모든 등급에 크고 진한 원판(등급 색 그대로 + 짙은 테두리 + 두께). 예전에는 노말은 원판이 없고 나머지도 옅었다. 병과 색 띠와 발 앞 풀 장식은 원판을 가려서 뺐다(병과는 이름표의 동그라미 글자로 본다).
- **바로 조합 버튼**(`main.js` `renderInfo`): 유닛 카드에 "같은 병과 조합"(초록) · "랜덤 조합"(보라) 두 버튼과 짝의 수. 짝이 없으면 회색으로 눌리지 않는다. 누르면 짝 하나와 조합해 결과가 고른 유닛의 자리에 선다. 다른 병과 짝 가운데 용사·히든 조합이 되는 것이 있으면 "★ 특별 조합"(주황)으로 바뀌고 그 짝을 먼저 쓴다. 용사를 골랐으면 "용사 각성". 유닛 + 유닛을 차례로 눌러 조합하는 방식도 그대로 된다.
**검사**: 규칙 검사 3-16 추가(칸 지정 소집, 찬 칸·남의 칸은 안 됨). 브라우저에서 빈 칸 누르기 → 그 칸에 소집, 유닛 고르기 → 버튼 상태(켜짐/회색), 같은 병과 조합 · 랜덤 조합이 실제로 되는 것을 두 화면 크기에서 자동 확인. 짧은 화면에서 카드가 전장을 5px 덮어서 줄인 카드의 버튼 높이를 줄였다(화면 검사 문제 기기 0). `npm test` 통과.
**남은 한계**: 실제 기기 미확인. 빈 칸을 잘못 눌러도 바로 소집된다(되돌릴 수 없다). 원판을 이름표가 조금 가린다. 노말(회색) 원판은 초원 발판 위에서 다른 등급보다 덜 눈에 띈다. 바로 조합은 짝이 여럿일 때 어느 짝을 쓸지 고를 수 없다(칸 번호가 앞선 것) — 고르고 싶으면 유닛 + 유닛 방식으로.

## 2026-11-21 — 군별을 고르지 않고 여섯 군별이 섞여 나오게, 조합은 같은 군별끼리만 (대규모 규칙 변경)
**경위**: 사용자 — "전투 시작 시 육군·의경 등을 선택하고 그 군별만 나오잖아. 이걸 선택하지 않고 모든 군별이 나오게 해 줘. 그런데 조합은 같은 군별끼리만 되도록. 대규모 패치지만 부탁해".
**규칙** (`core.js`)
- 유닛마다 군별 `u.b`가 있다. 소집하면 여섯 군별 가운데 무작위(`pickBranch`). 군별 특성·계급 이름·병과 이름·히든 계급은 그 유닛의 군별 것을 쓴다(`branchOf(g, u)`).
- `canMerge`: 같은 등급 **그리고 같은 군별**. 결과 유닛은 그 군별을 이어받는다. 진급 심사·병과 교체를 해도 군별은 그대로. 용사·히든 조합도 같은 군별끼리.
- `createGame`에 `branchId`를 주지 않으면 섞이는 판(`g.only = null`). 주면 그 군별만 나오는 판 — 검사와, 군별을 고르던 시절에 저장한 판을 이어 할 때 쓴다(옛 저장은 `only`가 없어 그 군별만 나오는 판으로 이어진다).
- 의경 특성의 "처치 보상 +10%"는 의경 유닛이 전장에 하나라도 있으면 적용. 군별 표창은 "그 군별 유닛 공격력 +n%".
- 숙련 경험치는 군별마다 따로 쌓인다(피해 기록 `dmgT`의 이름이 `군별:병과`). 협동도 군별을 고르지 않는다.
**화면** (`main.js` · `render.js` · `sprites.js`)
- 출격 화면에서 군별 고르기를 없앴다(작전 · 난이도 → 출격). 협동 대기실의 "내 군별"도 없앴다.

## 2026-11-20 — APK가 "앱이 설치되지 않음"으로 깔리지 않는 문제 → 시험 빌드를 고정 키로 서명
**경위**: 사용자에게 Actions가 만든 최신 APK를 전달 → 기기에서 "앱이 설치되지 않음".
**원인(확인함)**: 서명이 빌드마다 다르다. `android.yml`은 고정된 키 없이 `assembleDebug`를 돌려서, Actions 실행기마다 새 디버그 키가 만들어진다. `apksigner verify --print-certs`로 연속한 두 빌드의 인증서 지문이 다른 것을 확인했다(1547eb… / 1ae3fa…). Android는 서명이 다른 파일을 기존 앱 위에 덮어 깔지 못한다.
**임시 조치**: 같은 APK를 이 작업 환경의 디버그 키(`~/.android/debug.keystore`, 지문 ed6899… — 2026-11-19에 직접 빌드해 사용자에게 준 APK와 같은 키)로 다시 서명해 전달했다(`apksigner sign --ks ~/.android/debug.keystore --ks-pass pass:android --ks-key-alias androiddebugkey`). 사용자 기기에 깔린 것이 그 파일이면 덮어 깔린다. 아니면 기존 앱을 지우고 깔아야 한다(저장 데이터 사라짐).
**근본 해결(사용자 승인 "응 진행해 줘")**: 그 디버그 키를 `android/app/debug.keystore`로 저장소에 넣고 `android/app/build.gradle`의 `signingConfigs.debug`가 그것을 쓰게 했다. 이제 Actions든 어느 컴퓨터든 시험 빌드의 서명이 같다. **이 파일을 지우거나 새로 만들지 않는다** — 바꾸면 이미 깔린 시험판 위에 덮어 깔 수 없게 된다. 출시용 서명 키와는 별개이며 출시용 키는 저장소에 두지 않는다.
**검사**: 고친 뒤 Actions가 만든 APK의 인증서 지문이 고정 키와 같은 것(ed6899…)을 `apksigner verify --print-certs`로 확인. 같은 커밋의 main 빌드는 Maven 저장소의 429(요청 과다)로 한 번 실패해 다시 돌렸다(변경과 무관).
**남은 한계**: 사용자 기기에 지금 깔린 앱이 이 키로 서명된 것이 아니면 처음 한 번은 지우고 깔아야 한다(저장 데이터 사라짐). 그 뒤로는 덮어 깔린다. 게임 내용은 앱이 켜질 때 자동으로 받으므로 APK를 새로 깔 일은 앱 이름·아이콘·광고 같은 앱 껍데기가 바뀔 때뿐이다.
